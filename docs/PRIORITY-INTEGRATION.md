# מסך Priority — נוהל הפעלה

מסך `/priority` מציג את נתוני ההנהלת-חשבונות מ-Priority ERP: תנועות יומן,
חשבונות, מסמכים, ויתרות. **קריאה בלבד.**

---

## איך הנתונים מגיעים

```
Priority ERP  ──ייצוא כרטסת ידני──►  sync_kartesset.py  ──►  Supabase
                                                            (priority_mirror)
                                                                  │
                                          server/src/routes/priority.js
                                                                  │
                                              client/src/pages/Priority.tsx
```

**למה לא ישירות מ-Priority:** קריאות ל-API של Priority נספרות במכסת הטרנזקציות
של החברה — מסך שמושך חי בכל רענון הוא עלות, לא פיצ'ר. בנוסף, ה-API חסום כרגע
ברמת מודול: Basic auth אסור כש-External ID פעיל, ו-PAT/OAuth2 דורשים מסכים
שאינם מותקנים בטננט. זה גבול מסחרי, לא פער בקוד.

**למה דרך השרת ולא מהדפדפן:** הקרדנציאלים של המראה נשארים בשרת. דפדפן שמחזיק
אותם חושף את כל הנתונים הפיננסיים לכל מי שפותח DevTools.

---

## משתני סביבה

ארבעה, **כולם נדרשים יחד**. חסר אחד — המסך מציג "החיבור למראה אינו מוגדר"
(HTTP 503) במקום להיכשל בשקט.

| משתנה ב-CRM | מקורו |
|---|---|
| `SUPABASE_URL` | `SUPABASE_URL` |
| `SUPABASE_ANON_KEY` | `SUPABASE_ANON_KEY` |
| `PRIORITY_MIRROR_EMAIL` | `HERMES_EMAIL` |
| `PRIORITY_MIRROR_PASSWORD` | `HERMES_PASSWORD` |

הערכים נמצאים ב-`priority-integration/dist-skill/tzevet-yahalom-crm/.env`
(בסביבת העבודה של HERMES). שמות המשתנים שונו כי "HERMES" חסר משמעות בהקשר
של ה-CRM.

**ב-Render:** ארבעתם כבר מוצהרים ב-`render.yaml` עם `sync: false` — כלומר
הערכים מוזנים ידנית בלוח הבקרה של Render ואינם נשמרים ב-repo.

## הרשאות

`page:priority` → `admin`, `manager` בלבד.

**שתי שכבות, ושתיהן נחוצות:** `usePermissions.ts` מסתיר את הפריט בתפריט (נוחות),
ו-`requireManager` בשרת אוכף (אבטחה). המסתיר לבדו אינו הגנה — נתיב ישיר ל-API
היה עוקף אותו.

## עדכניות הנתונים — ההבחנה המרכזית

המסך מציג **שני מספרים שונים לשתי שאלות שונות**:

- **`dataAsOf`** — תאריך התנועה האחרונה. *עד מתי הנתונים נכונים.*
- **`lastRun.started_at`** — *מתי רצה הטעינה.*

הם אינם זהים. אפשר לטעון היום ייצוא שהתנועה האחרונה בו בת חודש; מסך שמציג רק
את השני היה מכריז "עודכן היום" על נתונים ישנים.

הבאנר בראש המסך: ✅ עד 7 ימים · ⚠️ עד 31 · 🔴 מעבר לכך.

**לרענון:** ראה `priority-integration/HOWTO-KARTESSET-SYNC.md`. בקצרה — להפיק
כרטסת מפריוריטי (בשדה **חשבון** להזין `*`; ריק מחזיר דוח **ריק**), ואז:

```bash
python sync_kartesset.py --commit
```

## מלכודות

- **`יתרת לקוחות` אינו מלוא החשיפה.** ה-view מחשב נאמנה את מה שבכרטסת, אבל
  חשבון עסקה אינו נכנס לכרטסת, 2024 סגורה, והעוסק המורשה אינו כלול כלל.
  לכן הכרטיס נושא הסתייגות מפורשת — בלעדיה המספר מוביל למסקנה שגויה.
- **סיכומים באים מ-`v_summary`, לא מסכימת השורות שנטענו.** סכימת חלון של
  100 שורות מציגה חוב נמוך מהאמת, וזה נראה סביר לגמרי על המסך.
- **RLS שדוחה מחזירה 200 עם מערך ריק** — "אין הרשאה" ו"אין נתונים" נראים זהים.
  לכן השרת זורק שגיאה אמיתית והמסך מבחין בין השניים במפורש.
- **מסמכים מבוטלים נשארים בטבלה.** `/documents` מסנן `cancelled=is.false`
  כברירת מחדל; `?includeCancelled=true` כדי לראות הכל.
